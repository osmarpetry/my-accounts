# MSW Migration Documentation

## Overview

This project has been successfully migrated from Next.js API routes to **Mock Service Worker (MSW)** for API mocking. MSW provides better network-level interception and more realistic testing scenarios.

## What Changed

### ✅ Added
- **MSW handlers** in `src/lib/msw/handlers/`
  - `accounts.ts` - Handles all account-related API endpoints
  - `transactions.ts` - Handles transaction endpoints
  - `transfers.ts` - Handles transfer endpoints
  - `index.ts` - Combines all handlers

- **MSW setup** in `src/lib/msw/setup/`
  - `browser.ts` - Browser-side MSW worker setup
  - `server.ts` - Node.js/SSR MSW server setup
  - `index.ts` - Universal initialization function

- **MSW Provider** in `src/components/msw-provider.tsx`
  - Initializes MSW conditionally based on environment
  - Shows loading state during initialization

- **Service Worker** in `public/mockServiceWorker.js`
  - Generated by MSW for browser interception

### 🔄 Modified
- **Next.js Config** (`next.config.ts`)
  - Added `transpilePackages: ['msw']` for proper MSW compilation
  - Removed temporary build error ignoring flags

- **Root Layout** (`src/app/layout.tsx`)
  - Added `MSWProvider` wrapper for MSW initialization

### ❌ Removed
- **API Routes** (all routes in `src/app/api/`)
  - Completely deleted Next.js API routes
  - Original logic moved to MSW handlers

## How It Works

### Development Mode
1. MSW automatically initializes when the app starts
2. All API requests to `/api/*` are intercepted by MSW
3. MSW handlers provide the same functionality as the original API routes
4. Loading state is shown during MSW initialization

### Production Mode
- MSW is disabled by default in production
- Can be enabled by setting `NEXT_PUBLIC_API_MOCKING=enabled`

## API Endpoints

All original endpoints are preserved with identical functionality:

### Accounts
- `GET /api/accounts` - List and search accounts
- `POST /api/accounts` - Create new account
- `GET /api/accounts/[id]` - Get specific account
- `PUT /api/accounts/[id]` - Update account
- `DELETE /api/accounts/[id]` - Delete account

### Transactions
- `GET /api/transactions` - List transactions (with optional accountId filter)
- `POST /api/transactions` - Create transaction

### Transfers
- `GET /api/transfers` - List transfers
- `POST /api/transfers` - Create transfer between accounts

## Environment Variables

```bash
# Enable MSW in production (optional)
NEXT_PUBLIC_API_MOCKING=enabled
```

## Benefits of MSW

1. **Network-level interception** - More realistic than API route mocking
2. **Works in both browser and Node.js** - Consistent across environments
3. **Better testing** - Can be used in unit tests, integration tests, and E2E tests
4. **Development flexibility** - Easy to enable/disable mocking
5. **Production debugging** - Can be enabled in production for debugging
6. **Cleaner codebase** - Removed API route clutter from the codebase

## Troubleshooting

### MSW Not Working
1. Check browser console for MSW initialization messages
2. Ensure `public/mockServiceWorker.js` exists
3. Verify MSW is enabled in development mode

### API Requests Failing
1. Check if MSW handlers are properly registered
2. Verify request URLs match handler patterns
3. Look for MSW warning messages about unhandled requests

### Build Issues
1. Ensure `transpilePackages: ['msw']` is in `next.config.ts`
2. Check for TypeScript errors in MSW handlers
